Experiment Analyzer — Appwrite Databases Hackathon Build Guide
A four-day build plan for a small, rigorous A/B-test analysis tool on Appwrite TablesDB. Prepared 27 October 2026. The hackathon deadline is Saturday 31 October at 11:59 PM PT, which is about 12:29 PM IST on Sunday 1 November; aim to submit on Saturday evening IST. This is a separate, new project (hackathon rules require entirely new code), and the statistics logic can later seed Phase B of DecisionPilot.
1. The project in one page
1.1 What it is
Experiment Analyzer takes the results of an A/B test, asks you to declare your hypothesis before it looks at the numbers, and then returns a verdict you can defend: significant, not significant, inconclusive, or invalid. It chooses the right statistical test, checks that test’s assumptions, reports the effect size with a confidence interval, and says plainly what the result does and does not tell you.
1.2 The one-sentence pitch
“Most A/B tests get called wins on noise; Experiment Analyzer makes you state the hypothesis first, checks the maths, and tells you honestly when the data cannot answer the question.”
1.3 Why this fits the hackathon
Judging criterion
How this project answers it
Idea and innovation
Pre-declared hypotheses, an honest “inconclusive” verdict, a sample-ratio-mismatch guard, and a statistics engine whose own error rates are measured and published
Technical execution
A tested Python statistics function, a validation script that simulates thousands of experiments, and a typed data model
Design and experience
One clear verdict banner, a confidence-interval picture, plain-language explanations, and three one-click demo experiments
Usage of Appwrite Databases
TablesDB with typed columns, relationships, row-level permissions, public sharing through permissions, indexed queries with pagination, and realtime updates
1.4 What it is not
It is not DecisionPilot, and it does not train models or call an LLM. It is a small, finished tool. Finishing a narrow thing well beats half-building a large one, and the judging page says the same: a well-executed idea with a thoughtful experience can win.
1.5 What a user does
Opens the site and presses Try a demo (an anonymous Appwrite session, so no sign-up friction), or signs in.
Uploads or pastes a CSV with a group column and an outcome column, or loads a built-in example.
Maps the columns and declares the hypothesis: metric type, direction, significance level, and the smallest effect that would matter to the business.
Presses Analyse. The statistics function runs and the result is saved to TablesDB.
Reads the verdict, the interval picture, the assumption checklist and the caveats.
Optionally turns on Share to get a public read-only link, and sees past analyses in a history list.

One database fits the Free plan, the data is structured, and TablesDB gives typed columns, relationships, row-level permissions and realtime

SciPy gives exact, well-tested tests (Welch, Mann-Whitney, permutation, bootstrap); JavaScript statistics libraries are thinner and easier to get wrong

The statistics must be deterministic and testable, and a language model adds nothing the engine needs

5. The statistics engine specification
The engine is one Python function that receives numbers and returns a StatResult. It never trusts the user’s choice of test blindly: it decides from the data type and the assumption checks.
5.1 Inputs
{ &quot;metricType&quot;: &quot;continuous&quot;, &quot;a&quot;: [12.1, 9.8, ...], &quot;b&quot;: [13.4, 11.2, ...], &quot;labels&quot;: [&quot;control&quot;, &quot;variant&quot;], &quot;alpha&quot;: 0.05, &quot;alternative&quot;: &quot;two-sided&quot;, &quot;minEffect&quot;: 0.5, &quot;expectedRatio&quot;: 0.5, &quot;seed&quot;: 42}
For binary metrics, a and b are arrays of 0 and 1 (or the function accepts counts of successes and totals). Cap each array at 20,000 values; if the user uploads more, the client samples nothing and instead warns, or aggregates binary data to counts, which loses nothing for proportion tests.
5.2 Step 1: validation
Remove missing and non-numeric values, and report how many were removed per group.
Require at least 10 values per group for continuous metrics and at least 20 per group for binary metrics; otherwise return verdict invalid with the reason.
Require two distinct groups. Warn when the groups are very unequal (ratio beyond 3 to 1).
5.3 Step 2: sample ratio mismatch
If the user declared an expected split (default 50/50), run a chi-square test of the observed group sizes against it. A p-value below 0.001 means the assignment is probably broken, so return invalid with the caveat “the groups are not the size they should be; the comparison may be biased”. This is the most common silent failure in real experiments and judges rarely see it handled.
5.4 Step 3: choose and run the test

Assumption checks recorded for the checklist: Shapiro-Wilk on up to 5,000 values per group, Levene’s test with the median centre (Brown-Forsythe), an outlier summary using the 1.5 times IQR rule, the sample ratio check, and the expected-count check for proportions. Each check stores name, passed, detail and actionTaken (for example “switched to Mann-Whitney”).
5.5 Step 4: verdict rules
Invalid: failed validation or sample ratio mismatch.
Significant: p below alpha, and the confidence interval excludes zero in the declared direction. If the user gave a minimum effect, add “and practically meaningful” only when the interval’s nearer end is beyond it.
Not significant: p at or above alpha, and the study could have detected the smallest effect that matters (the minimum detectable effect is no larger than minEffect).
Inconclusive: p at or above alpha, and the minimum detectable effect is larger than minEffect. The data cannot rule out an effect that would matter. If the user supplied no minEffect, default it to 0.2 standard deviations for continuous metrics and 1 percentage point for binary ones, and say so.
Minimum detectable effect, at 80 percent power, by the normal approximation: (z(1 - alpha/2) + z(0.80)) * sd * sqrt(1/nA + 1/nB) for continuous metrics, and the analogous formula with sqrt(p(1-p)) for proportions. Never report “observed power” from the result itself; it is a known fallacy and judges who know statistics will notice.
5.6 Output (StatResult)
{ &quot;test&quot;: &quot;welch_t&quot;, &quot;statistic&quot;: 2.31, &quot;pValue&quot;: 0.021, &quot;effectName&quot;: &quot;difference in means&quot;, &quot;effectValue&quot;: 0.84, &quot;ciLow&quot;: 0.13, &quot;ciHigh&quot;: 1.55, &quot;ciLevel&quot;: 0.95, &quot;mde&quot;: 0.62, &quot;verdict&quot;: &quot;significant&quot;, &quot;assumptions&quot;: [ {&quot;name&quot;: &quot;normality&quot;, &quot;passed&quot;: true, &quot;detail&quot;: &quot;Shapiro p=0.31 (control), 0.44 (variant)&quot;, &quot;actionTaken&quot;: &quot;none&quot;} ], &quot;descriptives&quot;: {&quot;a&quot;: {&quot;n&quot;: 480, &quot;mean&quot;: 10.2, &quot;sd&quot;: 3.1, &quot;median&quot;: 10.0}, &quot;b&quot;: {}}, &quot;caveats&quot;: [&quot;A significant result is not a guarantee of the same effect next time.&quot;], &quot;seed&quot;: 42, &quot;engineVersion&quot;: &quot;1.0.0&quot;}
The plain-language sentence shown to the user is generated by simple templates from these fields, not by a language model, for example: “The variant’s average was 0.84 higher (95 percent interval 0.13 to 1.55). The interval excludes zero, so the difference is unlikely to be noise.”

6.3 Core engine pieces
import numpy as npfrom scipy import statsENGINE_VERSION = &apos;1.0.0&apos;def clean(values): arr = np.asarray(values, dtype=float) arr = arr[np.isfinite(arr)] return arrdef hedges_g(a, b): na, nb = len(a), len(b) sp = (((na - 1) * a.var(ddof=1) + (nb - 1) * b.var(ddof=1)) / (na + nb - 2)) ** 0.5 d = (a.mean() - b.mean()) / sp return d * (1 - 3 / (4 * (na + nb) - 9))def cliffs_delta(a, b): u = stats.mannwhitneyu(a, b, alternative=&apos;two-sided&apos;).statistic return 2 * u / (len(a) * len(b)) - 1def wilson(x, n, z): p = x / n d = 1 + z * z / n c = (p + z * z / (2 * n)) / d h = z * ((p * (1 - p) / n + z * z / (4 * n * n)) ** 0.5) / d return c - h, c + hdef newcombe(x1, n1, x2, n2, z): p1, p2 = x1 / n1, x2 / n2 l1, u1 = wilson(x1, n1, z) l2, u2 = wilson(x2, n2, z) d = p1 - p2 return d - ((p1 - l1) ** 2 + (u2 - p2) ** 2) ** 0.5, d + ((u1 - p1) ** 2 + (p2 - l2) ** 2) ** 0.5def welch(a, b, alpha, alternative): res = stats.ttest_ind(a, b, equal_var=False, alternative=alternative) ci = res.confidence_interval(confidence_level=1 - alpha) return res.statistic, res.pvalue, a.mean() - b.mean(), ci.low, ci.highdef bootstrap_diff(a, b, alpha, seed, n_resamples=5000): def diff(x, y, axis): return np.mean(x, axis=axis) - np.mean(y, axis=axis) r = stats.bootstrap((a, b), diff, vectorized=True, n_resamples=n_resamples, confidence_level=1 - alpha, method=&apos;BCa&apos;, random_state=np.random.default_rng(seed)) return r.confidence_interval.low, r.confidence_interval.highdef srm_check(n_a, n_b, expected_ratio=0.5): total = n_a + n_b chi = stats.chisquare([n_a, n_b], f_exp=[total * expected_ratio, total * (1 - expected_ratio)]) return chi.pvaluedef mde_continuous(sd, n_a, n_b, alpha): z = stats.norm.ppf return (z(1 - alpha / 2) + z(0.80)) * sd * (1 / n_a + 1 / n_b) ** 0.5def mde_binary(p, n_a, n_b, alpha): z = stats.norm.ppf return (z(1 - alpha / 2) + z(0.80)) * (p * (1 - p)) ** 0.5 * (1 / n_a + 1 / n_b) ** 0.5
Verdict logic, written once and tested hard:
def decide(p, alpha, ci_low, ci_high, mde, min_effect, alternative): significant = p &lt; alpha and (ci_low &gt; 0 or ci_high &lt; 0 or alternative != &apos;two-sided&apos;) if significant: return &apos;significant&apos; return &apos;not_significant&apos; if mde &lt;= min_effect else &apos;inconclusive&apos;
For one-sided tests, report the one-sided interval the library gives and state in the caveats that a one-sided test was declared in advance. Do not let the user choose the direction after seeing the data; the declaration step locks it.
6.4 Engine tests (write these first)
Welch against a hand-computed example from a textbook or a spreadsheet.
Newcombe interval against a published worked example.
Sample ratio mismatch: 5,000 and 5,000 passes; 6,000 and 4,000 fails.
Tiny samples return invalid.
Identical groups return not_significant or inconclusive, never significant.
A skewed small sample triggers the Mann-Whitney path and records why.
Missing values are removed and counted.
The same seed gives identical bootstrap intervals.

7.3 The wizard
Data. Paste or upload a CSV, or press a demo. Parse in the browser, show the first rows and the row count, reject files over the cap with a clear message.
Mapping. Choose the group column, the outcome column and which value is group A and which is B. For binary outcomes, choose which value counts as success.
Hypothesis (locks on run). Metric type (detected, editable), direction, significance level, the smallest effect that matters, and the expected split. Add a one-line hypothesis text. After pressing Analyse these fields are saved with the result and cannot be edited, which is the pre-registration idea in miniature.
Review and run. A summary card of everything declared, then Analyse. Show a progress state, and warm the function with a tiny call when the page loads so the first run is not slow.
7.4 The result page
Build it top to bottom in this order, so the answer comes first and the evidence follows:
Verdict banner: one word, an icon, and one sentence. Colour supports the meaning but never carries it alone.
Effect and interval: the number, the interval, and the picture (section 7.5).
Plain-language reading: two or three sentences from templates.
Assumption checklist: each check with pass, fail or warning, what was found, and what the engine did about it.
Power card: the minimum detectable effect against the smallest effect that matters, with one sentence that says whether the test could have seen it.
Distributions: overlaid histograms (or box plots) for continuous data, bars for proportions.
Caveats and “what this does not tell you”.
Actions: Share, Download JSON, Download a one-page Markdown report, Run again with changes (creates a new analysis; the old one stays untouched).
7.5 The interval picture
A horizontal axis with a vertical line at zero, a shaded band for the smallest effect that matters, a dot for the estimate and whiskers for the interval. Label the zero line and the band directly. This single picture explains significance, practical importance and uncertainty at once, so give it care.
7.6 Plain-language templates (no LLM)
Significant: “{B} averaged {value} {higher|lower} than {A} (95 percent interval {low} to {high}). The interval excludes zero, so the difference is unlikely to be noise.”
Not significant: “No reliable difference was found. The interval runs from {low} to {high}, and this test could detect effects of about {mde} or more, so an effect as large as the one you care about would probably have shown up.”
Inconclusive: “The data cannot tell. The interval {low} to {high} includes zero and also effects as large as {minEffect}, and the test could only detect effects of {mde} or more. Collect more data before deciding.”
Invalid: “This comparison is not trustworthy: {reason}.”

10.2 Stretch: tamper-proof results
Because the browser saves the result, a determined user could edit the numbers before saving. For a stronger design, let the function write the row with a server API key (scopes limited to rows write on this table) and return only the row id. This is a good “what I would do next” line in the README even if you do not build it.
